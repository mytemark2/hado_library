# クローラー生成版とデータ受入検査（2026-10-31）

## 原因・恒久対策

生成器のリリース番号をJSONの互換性条件と混同し、状態変化タグと兵科横断検索の現行データ検査が `1.1.0.9` だけを許可していた。正常な `1.1.0.11` の保存済み生成データも拒否する検査側の不具合であり、データを旧版へ戻す対策は採らない。

`tools/crawler_data_contract.js` で対応schemaVersion、items配列、生成版の記録、必要なkindを検査する。派生20ファイルは同一生成版を要求するが、特定の版番号は要求しない。状態変化タグのqualityAudit・兵科技能・参照・件数など既存の内容検査は維持する。保存原本や継承した一次JSONの古い生成版を、新規取得版へ書き換えない。

旧 `tools/import_crawler_json.ps1` の `1.1.0.0` 固定も撤去し、対応schemaと取得報告／派生JSONの生成版一致に置換する。このツールの旧アプリ専用ブランチ制限・件数監査は維持し、現行CLIの取込経路へ転用しない。

## 影響・再発防止

- アプリの画面・HTML・JSON・保存形式・公開版は変更しない。表示版番号とアセットキーの更新対象ではない。
- `tools/test_crawler_data_contract.js` は旧版・現行版・将来の生成器識別子を受け入れ、不正schema、items、生成情報、kind、混在版を拒否する。固定条件が2つの現行検査や旧取込ツールへ戻ることも検出する。
- 全体検証 `tools/run_app_validation.py` に追加。GitHub App Validationも同じ検証を実行する。
- AGENTS.mdに「生成版は来歴情報、互換性はschema・構造・品質で判定」を明記する。
- 過去のJSON、報告、履歴用テスト入力の版番号は、ルールではなく証跡として保持する。
