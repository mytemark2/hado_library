# 3.1.0.0 r194 通常検索タグの原文同期・全タグ総点検 Implementation

## 目的

- 条件・発動タグを全データの明示原文から生成する。
- 「交戦開始時」を条件と発動へ重複表示せず、発動へ一意に分類する。
- 現在選択中の検索カテゴリに該当データが存在するタグだけを表示する。
- 武将検索用タグを1つずつ自動照合し、0件タグと所有者不一致を検出する。

## 実装

1. `hado_search_clause_integration.js`
   - `hadou_effect_condition_blocks.json`の`■`条件・`▼`発動マーカーを全件走査する。
   - 原文の条件と発動を別グループへ分類し、証跡となる原文を内部保持する。
   - LR・UR・覚醒・通常武将を混同しない完全一致キーを原文タグ用に追加する。
   - reviewed EffectClauseの条件評価ロジックは変更しない。
2. `hado_bootstrap.js`
   - 起動時に条件ブロックを検索タグ統合へ渡す。
3. `hado_status_effects.js` / `hado_core.js` / `hado_search.js`
   - 実際の所有者からタグ単位の対象カテゴリ索引を再構築する。
   - 所有者が0件のタグを候補から除外する。
   - タグ画面と入力候補を現在有効な検索カテゴリで絞り、カテゴリ変更時に再描画する。
4. `tools/test_3_1_0_0_tag_search_exhaustive.js`
   - 武将488件、通常検索で選択可能な939タグを1件ずつ照合する。
   - タグごとの期待所有者と単一タグ検索結果の完全一致を検査する。
   - 条件・発動タグはすべて`■`または`▼`の原文証跡を必須とする。

## 互換性

- タグ検索のグループ内OR・グループ間ANDを維持する。
- 選択済みタグ、検索履歴、保存データ、Export/Importの形式は変更しない。
- JSON、crawler、EffectClause schema、既存の条件成立評価は変更しない。

## 再発防止

- 全タグ単位の所有者照合をApp Validationへ追加する。
- 条件・発動タグの原文証跡を自動検査する。
- レアリティ違いを同一武将として集約しない完全一致キーを固定する。
- タグ選択肢はタググループ単位ではなく、個別タグの実所有カテゴリで判定する。

## 外部化判断

既存の責務別JavaScriptへ実装し、HTMLには`r194`キャッシュキーだけを反映する。新しいインラインJavaScriptは追加しない。
