# 3.1.0.0 r197 武将版違いの状態変化・Clause混入修正 Implementation

## 目的

状態変化検索でUR張角の会心耐性がLR張角と通常版張角へ混入する不具合を修正し、同じ識別方法を使うClause投影も含めて別レアリティ間の漏れ出しを恒久的に防ぐ。

## 原因

`hado_search_clause_integration.js`、`hado_formation_condition_evaluator.js`、`hado_clause_surface_bridge.js`が、読み仮名・空白に加えてLR/UR/SSR等のレアリティと括弧表記を除去した人物比較名を、個別レコードの索引キーにも使用していた。このため、`LR張角（ちょうかく）`、`UR張角（ちょうかく）`、`張角（ちょうかく）`が同じ索引へ入り、状態変化参照・確認済みClause・生成Clauseが相互に混入した。

## 実装

1. 個別レコード索引
   - NFKC正規化と空白除去だけを行う完全名キーを3つの共通処理へ追加する。
   - 状態変化参照、確認済みClause、生成Clause、画面投影キャッシュは完全名キーで保持する。
2. 人物比較
   - レアリティや読み仮名を除去する既存`comparableName`は、編成条件内の人物比較と状態変化名称の別名照合に限定して維持する。
   - 保存形式、JSON、人物条件の判定仕様は変更しない。
3. 全件再発防止
   - `tools/test_3_1_0_0_entity_identity_isolation.js`を追加する。
   - 全2,920状態変化対象エンティティ・5,342正規関連を各レコード固有の索引と照合する。
   - 全1,822 Clauseエンティティの確認済みケースと生成条件件数を元データと照合する。
   - 会心耐性の武将所有者がUR張角・UR曹洪・UR兀突骨の3名だけであること、LR張角の通常検索文字列へ会心耐性が入らないこと、LR袁紹の確認済みClauseがUR袁紹へ入らないことを負例として固定する。

## 影響範囲

通常検索の補助検索文字列、状態変化検索、条件Clauseの詳細投影、部隊編成条件評価、型検索へのClause証跡接続。表示レイアウト、採点値、タグのAND/OR、保存データ、派生JSON、crawlerは変更しない。

## 外部化判断

既存の責務別JavaScript3ファイル内の索引生成を修正する。新しい実行時モジュールやHTML内インライン処理は追加しない。`index.html`は`r197`キャッシュキーへの更新だけとする。

## 再発防止

App Validationへ全件同一性監査を常設し、今後データが追加されても、別レアリティ・ORIGINS版・通常版間で状態変化キー、確認済みClause、生成Clause件数が1件でも混入した場合はCIを失敗させる。
