# 3.2.0.0 Update04 — 検索条件と結果一覧の再設計

**状態:** 実装・検証中。表示版 `3.2.0.0 Update04 r217`。正式公開なし。

## 目的

検索モード、キーワード、カテゴリ、状態変化、型条件、タグ、表示範囲を一覧で把握し、不要な条件をその場で1件ずつ解除できるようにする。結果カードはカテゴリ、名称、一致理由を先に示し、補足情報が判断を妨げない順序へ整える。

## 起点

- 正本ブランチ: `feature/app-3.2.0.0`
- 開始HEAD: `73fadb6d430e5bcf1af25985910f1f852a5a7bc9`
- 作業ブランチ: `codex/3200-update04-search-results`
- 表示版: `3.2.0.0 Update04 r217`
- データ更新: なし。Update03で検証済みのデータ一式を継続使用する。
- 正式版反映: 対象外。全Update完了後に別途承認を得る。

## 実装範囲

1. 通常検索、状態変化検索、型検索の条件要約を同じチップ文法へ統一する。
2. キーワード、カテゴリ、タグ、状態変化、型条件、保存データ範囲、名称のみ条件を個別解除できるようにする。
3. 結果カードをカテゴリ・名称・一致理由・一致タグ・補足の順に再構成する。
4. 複数タグは選択中の同一タグに同一色を割り当て、既存画面の青・緑系と混同しない暖色・紫系12色を維持する。
5. コピー操作を `検索結果をコピー` と `検索条件リンクをコピー` に改称する。
6. PC・スマートフォンで条件チップ、解除操作、結果カード、コピー操作が横にはみ出さないようにする。

## 完了条件

- 適用中の条件が1件ずつ識別でき、各解除操作が元の検索状態へ反映される。
- 通常・状態変化・型検索の結果で、カテゴリ、名称、一致理由が補足より先に表示される。
- 複数タグの一致箇所が安定した別色で識別できる。
- コピー操作の用途が名称から判別できる。
- App Validation、検索・詳細・保存互換・Export/Import・編成回帰が合格する。
- 自動Preview同期、marker、表示版、公開URLのPC・スマートフォン実動作が合格する。
- Roadmap、implementation、reportへ結果と残件を記録する。

## 推奨エンジン

GPT-6.1 Sol（high）。検索状態、既存の3検索モード、レスポンシブ表示、回帰テストを横断しつつ、Astraよりクレジット消費を抑えられるため。
