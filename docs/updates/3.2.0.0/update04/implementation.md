# 3.2.0.0 Update04 実装記録

## 設計判断

- 新しい検索状態を作らず、既存のキーワードクリア、カテゴリ切替、タグ削除、状態変化解除、型条件削除、表示範囲切替を条件チップから呼び出す。
- 条件解除はイベント委譲で1回だけ登録し、チップの再描画ごとにイベントを重複登録しない。
- 結果カードから既存情報を削除せず、カテゴリ・名称・一致理由を一次情報、タグと補足を二次情報として表示順と視覚階層を変更する。
- タグ配色は既存の安定割当12色を使用し、青・緑中心の画面操作色と区別する。
- HTMLへ検索処理を追加せず、挙動は `hado_search.js`、タグ条件は `hado_status_effects.js`、表示は `hado_styles.css` に外部化する。

## 実装内容

- 通常検索のキーワード、カテゴリ、保存データ、名称のみ、タグを個別解除できる条件チップへ変更した。
- 状態変化検索のモード、選択状態変化、カテゴリ、保存データ、タグを個別解除できるようにした。
- 型検索のモード、プリセット、カテゴリ、状態変化、型要素、保存データ、タグを個別解除できるようにした。
- 通常検索と型検索の結果カードで、一致理由を名称直後へ移動した。副題、保存状態、戦法補足等は二次情報として後段へ配置した。
- スマートフォンでは解除ボタンを32px、コピー操作を44px以上とし、条件チップの横はみ出しを抑止した。
- `一覧コピー` を `検索結果をコピー`、`検索リンクコピー` を `検索条件リンクをコピー` に変更した。
- 初回Preview確認でキーワード条件チップの×が既存ボタンへの合成クリックに依存して動作しないことを検出した。キーワード解除処理を `clearKeywordSearchCondition` へ一本化し、チップと既存クリアボタンの双方から直接呼び出すよう修正した。
- 修正commitを同じ `04-r217` キャッシュキーで配信した際、公開ブラウザーが旧JavaScriptを再利用した。利用者向けPreviewビルドの原則どおりrevisionをr218へ進め、HTML内の全アセットキーを `04-r218` に更新した。
