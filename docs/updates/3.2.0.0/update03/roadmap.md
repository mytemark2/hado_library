## 目的

## 実装範囲

1. 取得・検証・反映を独立した状態としてデータ管理画面へ表示する。
2. 前回検証済みデータと現在データの武将・技能・兵科を、追加・変更・削除に分けて表示する。
3. 新規データは画面反映完了後にだけキャッシュへ確定し、失敗時は旧キャッシュを保持する。
4. 取得日時、処理日時、派生生成日時、run ID、bundle ID、生成元commitの役割を分離する。
5. Update01の保留事項を監査表示する。未分類8件は推測せず、戦法20件は保持し、同名装備2記事は別IDで索引化する。
6. 生成元で21派生JSONを一式再生成し、個別手修正を行わない。
