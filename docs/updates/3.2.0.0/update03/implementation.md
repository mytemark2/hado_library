# 3.2.0.0 Update03 実装記録

## 設計判断

- `hado_data_update.js` を新設し、差分、来歴、監査、表示を外部JavaScriptへ集約した。HTMLへ大型処理は追加していない。
- 差分識別子は記事ID等の安定IDを優先し、名称だけで同名レコードを統合しない。
- HTTP取得ではmanifestの件数・SHA-256・構造を検証し、アプリ側の完全な派生契約はApp Validationで保証する。
- キャッシュ更新は「取得成功」ではなく `applyLoadedData` の反映完了後に実行する。
- 既存r215以前のキャッシュは戦法一次JSONを持たなくても起動できるよう、`hadou_tactics.json` は追加監査用の任意ファイルとした。

## 実装内容

- データ管理画面へ取得・検証・反映、取得/処理/生成日時、dataset/run/bundle、前回差分を表示する。
- 武将、技能、兵科の追加・変更・削除と前後件数を算出する。
- 取得または検証失敗時は明示警告を表示し、検証済みキャッシュへフォールバックする。
- 反映前の候補データを一時保持し、反映成功後だけIndexedDBキャッシュへ確定する。
- Update01監査残差として、未分類状態変化、保持戦法、同名装備記事、過去runの不明なクローラーSHAを表示する。
- クローラー側で来歴項目を分離し、今後のrunではクローラーcommit/branchを記録する。
- 同名装備 `article-346228` と `article-381628` を一次配列位置とURLで別々に索引化する。
- 2026-10-17の取得済み入力から20派生索引と `hadou_effect_clauses.json` を含む21ファイルを一式再生成した。

## 再発防止

- 同名別記事、来歴契約、実データの未分類8件・戦法478/458/20件・装備2記事を固定テストへ追加した。
- Webキャッシュテストへ「反映成功前に永続化しない」契約を追加した。
- `dataUpdateStatusPanel` をアプリ自己診断の必須DOMへ追加した。

## 互換性

- JSONの既存top-level `items` とschemaVersion 1.0を維持する。
- 保存データ形式、Export/Import形式、検索・詳細・編成の既存DOM契約は変更しない。
- `hadou_tactics.json` は任意読込のため、旧キャッシュを無効化しない。

## HTMLと外部化

- HTML変更は外部スクリプト読込とキャッシュキー更新のみ。
- 実装は `hado_data_update.js`、`hado_bootstrap.js`、`hado_core.js`、`hado_styles.css` に外部化した。
- HTMLサイズ差は最終報告で起点SHAと比較して記録する。
