# 3.2.0.0 Update01 Implementation

## 計画時点

- 状態: 未実装
- 対象: 最新仕様・取得データの全件差分監査
- 正本ブランチ: 開始時に確認。現時点で実装ブランチは作成していない。
- 起点commit / 正式版: Update開始時にmainを確認して記録する。

## 実施方針

- クローラーの完了済み取得を先に確認し、完了済みデータがあれば再取得を避ける。
- 一次データを正本として、派生JSONを生成元から一式で監査する。
- 新規兵科名だけをテストするのではなく、兵科・技能・所有武将・検索カテゴリ・詳細参照の関係を横断して検証する。
- 追加・変更・削除、未分類、重複、参照切れを別々に記録する。
- 取得成功とアプリ反映成功を別の状態として扱う。
- JSON契約の変更が必要な場合はクローラー側の正規生成処理を対象に含める。アプリ側の生成JSONを手編集しない。
- 未確認の仕様を推測して入力せず、根拠のないケースは要確認として残す。

## 予定する再発防止

監査で検出した欠落・誤分類の欠陥クラスに応じて、正規のデータ生成テストとアプリ検索・詳細の回帰テストを追加する。単なる手順チェックリストではなく、誤った状態を検出して検証を失敗させる仕組みにする。
