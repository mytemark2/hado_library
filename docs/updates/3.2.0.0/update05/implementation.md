# 3.2.0.0 Update05 実装記録

## 1. 実装方針

既存の分割済みランタイムを拡張し、HTMLへ新規ロジックを埋め込まない。派生JSONと保存形式は変更しない。r219の重複説明抑止と共通技能レベル解釈を維持し、利用者動線をr220、一致元優先順位をr221、固有名節の分類をr222、内蔵検証をr223で修正した。r224では一致語特定と強調を追加し、r225ではPC詳細欄の直接スクロールへ修正する。

## 2. r220 利用者動線修正

### 2.1 タブと検索一致

- 武将タブをUpdate04時点の `概要 → 変化率 → 基礎 → 戦法 → 技能 → その他` へ復元した。
- 技能タブを `変化率 → 内容詳細` へ復元し、技能の初期表示は `内容詳細` を維持した。
- キーワード一致理由へ `keywordMatchTab` を保持し、検索結果選択時に該当タブを自動表示するようにした。
- 詳細上部へ検索一致理由と「一致箇所を表示」を追加した。
- 手動選択タブをカテゴリごとに保持し、操作履歴にも `detailActiveTab` を保存した。

### 2.2 常時表示の要約

- 武将詳細上部に兵科・天賦・おすすめ編制の要約を追加した。
- 詳細な能力値や五行適正は従来どおり基礎タブに残した。

### 2.3 参照技能の同一階層化

- 親技能内の `参照技能` 入れ子グループを削除した。
- 親技能と付与技能を同じカード一覧に表示した。
- 付与技能には `親技能名から付与` と `data-referenced-from` を残した。
- 武将詳細・技能直接詳細の双方で、技能レベル切替に連動する参照技能パネルを同一階層へ配置した。

### 2.4 維持したr219改善

- 直接技能詳細の同一説明重複抑止。
- 二次情報の `補足情報` 折り畳み。
- `renderSkillLevelToggleForItem` による武将・技能・編成の共通技能レベル解釈。
- 実在しない技能レベルの除外。

### 2.5 r221 公開Preview残件の補正

- r220公開Previewの `轟名` 検索で、検索用の `description` が画面内の技能節より先に一致し、概要タブが開くことを検出した。
- 一致理由候補の順序を、画面に表示できる節 → 表 → 検索用要約 → 生データの順へ変更した。
- 表は技能行、戦法表、基本情報表を内容から分類し、該当タブへ対応させた。
- 検索用要約と技能節の両方に同じ語があるfixtureを追加し、技能節が優先されることを回帰化した。

### 2.6 r222 固有名節の分類補正

- r221公開Previewで `轟名` の節見出しが一般節と判定され、概要タブが開くことを検出した。
- 節見出しを `getOwnedSkillLevelMapFromTables` の所有技能名と照合し、一致時は技能タブへ分類する。
- 節見出しを `findTacticName` の戦法名と照合し、一致時は戦法タブへ分類する。
- `轟名` と `強盛莫敵` の固有名節fixtureを追加した。

### 2.7 r223 内蔵検証の実経路化

- r222公開Previewの内蔵検証で `技能検索自動選択時の内容詳細タブ保持` が1件失敗した。
- 実画面の検索・タブ選択は正常であり、失敗原因は `renderSearchResults` の旧実装断片を関数文字列から探す検証にあった。
- 内蔵検証を `buildKeywordMatchDetail`、`applyResultRowDetailSelection`、`resolveDetailTabForSelection` の実行結果で判定する方式へ変更した。
- 記憶済みの変化率タブがあってもキーワード一致時は内容詳細を優先し、キーワードなしの直接遷移では記憶タブを維持する両方の規則を検証する。
- 静的回帰に、関数文字列依存へ戻っていないことと実選択経路を実行していることの検査を追加した。

### 2.8 r224 一致箇所へのスクロール

- 修正前公開Previewで `奮檄` を検索し、概要タブから「一致箇所を表示」を押すと技能タブへ移動するが、詳細欄の `scrollTop` は0、一致語は表示領域上端から2,271px下、表示領域外であることを確認した。
- 原因はボタン処理が `renderDetail()` でタブを再描画するだけで、再描画後の一致語を取得・スクロールする処理を持たなかったことにある。
- 対象タブ内だけから `mark.search-hit` を探索し、完全一致を優先して表示領域中央へ `scrollIntoView` する処理を追加した。
- 一致語が `details` 内にある場合は祖先の折り畳みを開いてから移動する。
- 移動先へ青いアウトラインと短いパルスを表示し、動きを減らすOS設定ではアニメーションを無効にする。
- 実際の対象選択、中央スクロール指定、再描画後の実行順を検証する `tools/test_3_2_0_0_update05_match_scroll.js` をApp Validationへ追加した。

### 2.9 r225 内部スクロール領域の直接制御

- r224公開Previewで同じ操作を再実施した結果、技能タブ切替と `奮檄` の強調クラス付与は成功したが、詳細欄は `clientHeight=226`、`scrollHeight=3157`、`scrollTop=0`、一致語は詳細欄下端より約2,049px下で表示領域外だった。
- 原因は、内部スクロール領域内のインライン `mark` に対する `scrollIntoView` の呼出しだけに依存し、詳細欄自身のスクロール結果を確認・制御していなかったことにある。
- 回帰テストも `scrollIntoView` が呼ばれたことだけをモックで確認し、詳細欄の `scrollTop` が変化する契約を検証していなかった。
- r225では詳細欄と一致語の `getBoundingClientRect()`、現在の `scrollTop`、表示高から中央位置を計算し、スクロール可能なPC詳細欄を `detail.scrollTo()` で直接移動する。
- 公開前のブラウザー実操作で `behavior: smooth` 指定時だけ内部スクロールが実行されず、`auto` 指定では同じ位置へ移動することを確認した。移動は即時実行し、到達位置は青い強調表示で認知できるようにする。
- 背景タブでは `requestAnimationFrame` が約2秒遅延したため、0msタイマーも併用し、先に実行できた経路だけが1回スクロールする排他制御を追加した。
- スマートフォンなど詳細欄自体がスクロール領域でない場合だけ、文書を移動する `scrollIntoView` をフォールバックとして使用する。
- スマートフォン幅ではレイアウト計算中に `scrollHeight` と `clientHeight` が4pxだけずれる場合があるため、16px以下の差は内部スクロールと判定せず文書スクロールへ送る。
- 回帰テストを、詳細欄への計算済み `top` とモバイルフォールバックの両方を検証する内容へ変更した。
