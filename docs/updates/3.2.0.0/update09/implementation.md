# Update09 実装記録

- `hado_formation_advice.js` に16評価項目、4用途の優先順位、編成差分、条件付き効果を分けた候補探索を追加。計算は最大1200候補の範囲で行う。採点は成立した効果の網羅度と、原文から確認できる上限・個別補正値を使う。
- `hado_formation_webmcp.js` に `hado_formation_context`、`hado_formation_search`、`hado_formation_evaluate` を追加。HTTPSの専用入口 `?chatgpt=formation` で選択中のセーブを利用者が許可すると、タブ内で20分間だけ参照できる。終了・セーブ切替・ページ移動で失効する。
- 許可済みのタブでWebMCPを使い、対応していないブラウザーには接続案内を表示する。r230で照会フォームを撤去した。ブラウザーエージェントの製品名はWebMCPから認証できないため、アクセスはタブと利用者の許可で制御する。
- 編成は既存の保存形式でセーブにひも付いていない。r230では主将が登録され、全武将・装備の所持と現行データを選択中のセーブで確認できる保存編成だけを連携に使用する。対象外の編成で使用中の武将・装備は引き続き保護し、対象外の編成に登録された兵器や陣形は開示・使用しない。セーブ切替はデータ管理の選択欄からも接続を解除する。
- 既存の侍従・装備判定と戦法・連鎖評価を再利用。通常の武器選択が使う関数に任意の編成引数を追加し、候補編成から同じ装備条件を判定できるようにした。所有判定には選択セーブの将星・段階を使い、候補評価は複製上で実行する。
- セーブ内に兵器・陣形の取得一覧がないため、基本陣形と保存編成で確認できる兵器・Lv・陣形・武装を使う。既存編成の名称やメモは連携の結果に含めない。戦闘式が未確認の初撃時間・間隔・兵器ダメージ・連鎖の被害総量は空値と理由を返す。
- `hado_version.js` をUpdate09 r229へ更新し、`index.html` のアセットキーと既存テスト12件の版期待値を変更した。HTMLは29,087→29,209バイト（+122）。新機能は外部JS2本と `hado_styles.css` の表示規則。既存保存形式、`HADO_DEV_INFO.json`、ゲームJSONはそのまま。
- `.github/workflows/notify-preview.yml` と既存の同期検査に新しいJS2本の必須ファイルチェックとハッシュ検証を接続した。
- 回帰を `tools/test_3_2_0_0_update09_formation_advice.js` と `tools/run_app_validation.py` に追加。履歴、セーブ、編成手順は既存テストを使用する。

## r231 技能Lvと戦法速度の計算修正

- `hado_formation.js` で武将・侍従・装備の採用と合算を先に行い、確定Lvに対応する取得本文を発動条件とともに解析する。駐屯・防衛の人数補正は主将・副将・補佐を対象とし、護厳は条件付き交戦開始効果として扱う。付与条件は計算式に表示する。

- `tools/test_3_2_0_0_formation_effect_calculation.js` を追加し、`tools/run_app_validation.py` に登録。既存テスト12ファイルの版期待値をr231に揃えた。

## r232 所持内の候補探索と一括保存

- `hado_formation_advice.js` と `hado_formation_webmcp.js` を拡張。安価な候補絞り込みの後、上位24件を既存画面の計算で再評価する。戦法速度・出陣ゲージ・兵器速度は数値比較し、被ダメージ上限などは根拠付きの評価を維持した。戦闘秒数・兵器実ダメージの未確認値は空欄。
- `hado_formation_save` を追加。候補IDはこのタブの接続内で期限付き。新規保存は別の実ユーザー操作で1回だけ許可する。保存前に所持情報・研究を含むセーブ、同じデータ、対象グループ、既存編成、装備・侍従配置を再確認する。保存エラー時は編集状態を戻し、同じ候補の再送では増殖させない。
- `hado_version.js` をr232へ更新し、`index.html` と既存版検証を同期した。HTMLの増減は0バイト。機能は既存外部JavaScriptを拡張した。変更試験は `tools/test_3_2_0_0_update09_formation_advice.js`。
