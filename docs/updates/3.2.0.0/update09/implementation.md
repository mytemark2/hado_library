# Update09 実装記録

- `hado_formation_advice.js` に16評価項目、4用途の優先順位、編成差分、条件付き効果を分けた候補探索を追加。計算は最大1200候補の範囲で行う。採点は成立した効果の網羅度と、原文から確認できる上限・個別補正値を使う。
- `hado_formation_webmcp.js` に `hado_formation_context`、`hado_formation_search`、`hado_formation_evaluate` を追加。HTTPSの専用入口 `?chatgpt=formation` で選択中のセーブを利用者が許可すると、タブ内で20分間だけ参照できる。終了・セーブ切替・ページ移動で失効する。
- ブラウザーのWebMCPを優先し、対応していない場合は許可後の専用入口で同じ3操作を実行する。静的サイトの公開機能として、ブラウザー上でChatGPTの製品名そのものを認証する仕組みはない。アクセスはタブと利用者の許可で制御する。
- 既存の侍従・装備判定と戦法・連鎖評価を再利用。通常の武器選択が使う関数に任意の編成引数を追加し、候補編成から同じ装備条件を判定できるようにした。所有判定には選択セーブの将星・段階を使い、候補評価は複製上で実行する。
- セーブ内に兵器・陣形の取得一覧がないため、基本陣形と保存編成で確認できる兵器・Lv・陣形・武装を使う。既存編成の名称やメモは連携の結果に含めない。戦闘式が未確認の初撃時間・間隔・兵器ダメージ・連鎖の被害総量は空値と理由を返す。
- `hado_version.js` をUpdate09 r229へ更新し、`index.html` のアセットキーと既存テスト12件の版期待値を変更した。HTMLは29,087→29,209バイト（+122）。新機能は外部JS2本と `hado_styles.css` の表示規則。既存保存形式、`HADO_DEV_INFO.json`、ゲームJSONはそのまま。
- `.github/workflows/notify-preview.yml` と既存の同期検査に新しいJS2本の必須ファイルチェックとハッシュ検証を接続した。
- 回帰を `tools/test_3_2_0_0_update09_formation_advice.js` と `tools/run_app_validation.py` に追加。履歴、セーブ、編成手順は既存テストを使用する。
